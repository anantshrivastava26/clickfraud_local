
# 🧠 Click Fraud Detection in Online Advertising (Data Orch)

### 🚀 Machine Learning Project — real-time fraud scoring, with an AWS (S3) data source

This project detects **click fraud** in online advertising traffic using **unsupervised machine learning**.
Click events stream into a **FastAPI** backend, are grouped into per-user sessions, and every finished session is
scored by an **Isolation Forest** model. Verdicts appear live on a **Streamlit** dashboard.

The model is trained offline on a sample of the **Avazu** ad-click log, which is pulled from **Amazon S3**.
Everything else runs locally, so you can try the demo without any AWS access.

> For the design, data flow, and trade-offs in depth, see **[architecture.md](architecture.md)**.

---

## 📜 Problem Statement

Online advertising platforms lose billions due to **fraudulent clicks** generated by bots or malicious users.
These fake clicks waste advertising budgets and distort campaign analytics.

The goal is to build a system that:
- Detects **anomalous click patterns** in ad traffic.
- Differentiates **human** vs **bot** behavior.
- Works **without fraud labels**, since real click logs don't have them.

---

## 🧠 Machine Learning Overview

### Model Used: **Isolation Forest**
- **Type:** Unsupervised anomaly detection (scikit-learn)
- **Why:** Needs no labels, which suits unlabeled ad-click data.
- **Config:** 200 trees, `contamination=0.02` (an assumed ~2% fraud rate that sets the decision threshold), fixed seed.
- **Unit of detection:** a **session** (all clicks from one user until they go idle), not a single click. One click says
  almost nothing; a burst of clicks across many ads does.

### Features
Each session is reduced to a feature vector (volume, ratio, breadth, device, timing). The model currently uses **15** of them:

| Group | Features |
|---|---|
| Volume / ratio | `impressions`, `clicks`, `click_rate` |
| Breadth | `unique_sites`, `unique_apps`, `c14_nunique` … `c21_nunique` |
| Device | `device_type`, `device_conn_type` |

Timing features (`session_length_secs`, `hour_*`, `interclick_*`) and `ua_len` are computed but were **constant in the
training data**, so they are dropped before training. See [architecture.md §6 and §10](architecture.md) for why.

## 🧪 Steps to Run

Trained artifacts are included, so steps 2–4 work **without AWS**. Run everything from the repo root.

### 1️⃣ Install

```bash
pip install -r requirements.txt
```

### 2️⃣ Start the backend

```bash
python receiver_fastapi.py        # http://localhost:8000
```

### 3️⃣ Generate traffic

```bash
python click_generator.py                    # humans + bots
python click_generator.py --mode bot         # bots only
```

### 4️⃣ Open the dashboard

```bash
streamlit run app_streamlit.py
```

Scroll to **🚨 Live Fraud Detection Feed**. A session is scored once the user has been idle for 30 s, or after 200 events.
Bots usually trigger the 200-event rule within seconds.

### 5️⃣ (Optional) Retrain from your own S3 data

```bash
# the CSV must be an Avazu-style click log
S3_BUCKET=my-bucket S3_KEY=train_sample.csv python train_isolation_forest.py
python eval_and_visualize.py      # regenerate plots + top_anomalies.csv
```

PowerShell: `$env:S3_BUCKET="my-bucket"; $env:S3_KEY="train_sample.csv"`. AWS credentials come from the usual boto3 sources
(environment, `~/.aws`, or an IAM role). On Windows, also change `LOCAL_TMP` in the script, which defaults to `/tmp/...`.
Restart the receiver and dashboard afterwards so they load the new model.

## 🔌 API

`POST /register_click` — send one click event:

```json
{
  "user_id": "bot-1",
  "ad_id": "site_42",
  "timestamp": "2025-10-13T09:18:03+00:00",
  "clicks": 1,
  "device_type": 0,
  "device_conn_type": 0,
  "device_model": "bot"
}
```

Response: `{"status": "ok", "pending_events_for_user": 3}`. Use a **timezone-aware** `timestamp` (with `+00:00`).
`GET /health` returns `{"status": "ok", "sessions_active": N}`. All fields are documented in [architecture.md §7](architecture.md).

## 📊 Results

* Training set: **~51,000 sessions** built from an Avazu click-log sample. About 2% are flagged by construction
  (`contamination=0.02`), and the very largest flagged sessions are huge-volume aggregates.
* In the sample live log included in the repo, **6 of 7 simulated-bot sessions** and **0 of 30 simulated-human sessions**
  were flagged. This shows the model reacts to the generator's bot profile (every impression clicked, many ads, long
  bursts). It is a demo, not a benchmark: there are no fraud labels, so precision and recall cannot be measured.

### ⚠️ Known limitations

* Timing signals are not used by the model yet. The `hour` field of Avazu (`YYMMDDHH`) is mis-parsed in training and is only
  hour-granular anyway.
* A few features (`unique_apps`, `c14`–`c21`) have no equivalent in the live click API and are filled with zeros.
* The receiver keeps sessions in memory, so it must run as a single process, and open sessions are lost on restart.
* The receiver has no authentication and listens on all interfaces. Keep it local.

Details and the full list are in [architecture.md §9–§10](architecture.md).

## ☁️ AWS

**In this repo:** Amazon S3 is the source of the training CSV (downloaded with `boto3`).

**Target cloud design** (not implemented in this repository):

| Service | Intended purpose |
|----------|----------|

---

## 🔒 Security Notes

* Never commit AWS credentials; use environment variables, `~/.aws`, or an IAM role with read access to the one bucket.
* The receiver is unauthenticated and binds to `0.0.0.0`; run it on a trusted machine or network only.
* `scored_sessions.jsonl` contains the user ids you send in; treat it accordingly.
